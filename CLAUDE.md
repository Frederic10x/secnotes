# SecNotes — Claude Code Context

## What this app is

Personal IT self-study app for career formation. Solo user, no authentication needed.
Frédéric is studying to work in IT (low-level systems, DevOps, CI/CD, infrastructure,
cybersecurity, networking, scripting). All fiche content must be relevant to this goal.
Fiches, flashcards and quizzes are generated by Claude Code CLI directly —
no Anthropic API integration in the app itself.

## Database — Tables Principales

Schema complet dans /supabase/schema.sql — ne jamais deviner les colonnes, toujours s'y référer.

```
nodes            → arborescence folders + fiches (self-referential parent_id)
fiches           → contenu markdown des fiches (1-to-1 avec nodes type=fiche)
tags             → tags globaux (#pentest, #appsec, #linux, #devops...)
fiche_tags       → liaison many-to-many fiches <> tags
flashcards       → cartes SM-2 liées à une fiche
quiz_questions   → questions QCM liées à une fiche
review_sessions  → historique sessions (flashcard + quiz) pour dashboard
user_preferences → 1 seule ligne : theme + font_size
```

Fonctions SQL disponibles :

- `get_node_progress(node_id)` → total_fiches, read_fiches, progress_pct
- `get_streak()` → int (jours consécutifs de révision)
- `global_search(query)` → résultats full-text cross-tables

## Supabase — Clients

Deux clients distincts, ne jamais les confondre :

```ts
// @/lib/supabase/server.ts — Server Components + Server Actions UNIQUEMENT
import { createClient } from "@supabase/supabase-js";
export const supabaseAdmin = createClient(
  process.env.NEXT_PUBLIC_SUPABASE_URL!,
  process.env.SUPABASE_SERVICE_ROLE_KEY!, // bypasse RLS — jamais exposé côté client
);

// @/lib/supabase/client.ts — Client Components uniquement (lecture)
import { createBrowserClient } from "@supabase/ssr";
export const supabase = createBrowserClient(
  process.env.NEXT_PUBLIC_SUPABASE_URL!,
  process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
);
```

Règle absolue : SUPABASE_SERVICE_ROLE_KEY uniquement côté serveur.
Jamais dans un Client Component, jamais dans une variable NEXT_PUBLIC_.

## Architecture Decisions

### Server vs Client Components

- Server Components par défaut pour tout fetch de données
- Client Components uniquement si : useState, useEffect, event handlers, animations
- Toujours utiliser les Server Actions pour les mutations (jamais d'API routes)

### Markdown Renderer

- Fichier unique : @/components/ui/MarkdownRenderer.tsx
- Gère : highlights ==texte==, callouts [!info/warning/danger/tip/note],
  code blocks avec bouton Copier, tables
- Specs dans /docs/CONTENT_RULES.md et /docs/UI_RULES.md

### Spaced Repetition (SM-2)

```ts
function sm2(easeFactor: number, intervalDays: number, quality: number) {
  const q = [0, 2, 4, 5][quality]; // 0=À revoir, 1=Difficile, 2=Bien, 3=Facile
  const newEF = Math.max(1.3, easeFactor + 0.1 - (5 - q) * (0.08 + (5 - q) * 0.02));
  const newInterval = q < 3 ? 1 : Math.round(intervalDays * newEF);
  return { easeFactor: newEF, intervalDays: newInterval };
}
```

## Pedagogical Focus — Domaines de formation

SecNotes sert à former Frédéric à l'IT. Chaque fiche doit être pertinente
avec un ou plusieurs de ces domaines :

| Domaine             | Exemples de sujets                                              |
| ------------------- | --------------------------------------------------------------- |
| Systèmes bas niveau | Permissions Linux, processus, mémoire, kernel, syscalls         |
| Réseaux             | TCP/IP, DNS, HTTP, TLS, firewalls, VPN, subnetting              |
| DevOps              | Docker, Kubernetes, CI/CD, pipelines, GitLab/GitHub Actions     |
| Infrastructure      | Terraform, Ansible, cloud (AWS/GCP/Azure), IaC, monitoring      |
| Cybersécurité       | Pentest, OWASP, vulnérabilités, forensics, CTF, hardening       |
| Scripting           | Bash, Python, expressions régulières, automatisation            |
| Développement       | Git, API REST, architecture, bases de données                   |

Règles de contenu :
- Toujours inclure l'angle sécurité/défensif/offensif quand pertinent
- Privilegier les exemples concrets : commandes réelles, chemins réels, syntaxes exactes
- Les flashcards doivent challenger la mémorisation active (pas juste "qu'est-ce que X")
- Les questions quiz doivent tester la compréhension, pas juste la définition
- Niveau de langue : technique, dense, sans remplissage — comme une doc de référence

## Workflow Création de Fiche — Protocole OBLIGATOIRE

Quand une création de fiche est demandée, suivre ces étapes DANS L'ORDRE.
Ne jamais sauter une étape. Ne jamais supposer qu'un node ou tag existe.

### Étape 1 — Vérifier/créer le thème

```sql
SELECT id, slug, color FROM nodes
WHERE parent_id IS NULL AND type = 'folder' AND slug = '[theme-slug]';
```

- Si trouvé → utiliser l'id existant
- Si absent → INSERT node (type='folder', parent_id=NULL, color=choisi, order_index=MAX+1)

### Étape 2 — Vérifier/créer le sous-thème

```sql
SELECT id, slug FROM nodes
WHERE parent_id = '[theme-id]' AND type = 'folder' AND slug = '[sub-slug]';
```

- Si trouvé → utiliser l'id existant
- Si absent → INSERT node (type='folder', parent_id=theme_id, color=hérité, order_index=MAX+1)

### Étape 3 — Vérifier/créer les tags

Pour chaque tag demandé :

```sql
SELECT id FROM tags WHERE name = '[tag-name]';
```

- Si trouvé → utiliser l'id existant
- Si absent → INSERT tag (name, color cohérente avec le domaine)

### Étape 4 — Générer le contenu

Générer les 3 fichiers dans scripts/tmp/ en suivant /docs/CONTENT_RULES.md :

- `scripts/tmp/fiche.md` → contenu markdown complet
- `scripts/tmp/flashcards.json` → 5 à 8 flashcards
- `scripts/tmp/quiz.json` → 3 à 5 questions QCM

### Étape 5 — Lancer le script d'import

```bash
npm run import-fiche -- \
  --theme "[theme-slug]" --subtheme "[sub-slug]" \
  --fiche scripts/tmp/fiche.md \
  --flashcards scripts/tmp/flashcards.json \
  --quiz scripts/tmp/quiz.json
```

### Étape 6 — Lier les tags

```sql
INSERT INTO fiche_tags (fiche_id, tag_id)
VALUES ('[fiche-id]', '[tag-id]')
ON CONFLICT DO NOTHING;
```

### Étape 7 — Confirmer

Output : "✅ [theme]/[sub]/[fiche-slug] — X flashcards, Y questions quiz"
Ne jamais laisser de fichiers dans scripts/tmp/ après import réussi.
Ne jamais demander à l'utilisateur de lancer le script manuellement.

## Format des fichiers tmp/

### fiche.md

Markdown brut suivant /docs/CONTENT_RULES.md.
Pas de frontmatter YAML. Commencer directement par le contenu (pas de titre H1).

### flashcards.json

```json
[
  {
    "question": "Quelle commande affiche les permissions d'un fichier en octal ?",
    "answer": "stat -c '%a %n' fichier — ex: 755 script.sh",
    "security_angle": "Les permissions 777 sont dangereuses : tout utilisateur peut modifier et exécuter le fichier."
  }
]
```

### quiz.json

```json
[
  {
    "question": "Que signifie le bit SUID sur un exécutable ?",
    "options": [
      "Il s'exécute avec les droits du propriétaire du fichier",
      "Il est lisible par tous les utilisateurs",
      "Il peut être modifié sans droits root",
      "Il s'exécute uniquement en mode kernel"
    ],
    "correct_index": 0,
    "explanation": "Le bit SUID force l'exécution avec les droits du propriétaire, pas de l'appelant. Vecteur d'escalade de privilèges courant en pentest.",
    "difficulty": 2,
    "tag": "linux"
  }
]
```
