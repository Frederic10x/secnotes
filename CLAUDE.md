# SecNotes — Claude Code Context

## What this app is

Personal cybersecurity self-study app. Solo user, no authentication needed.
Stores markdown notes in Supabase + mirrors to local Obsidian vault.
Fiches, flashcards and quizzes are generated by Claude Code CLI directly —
no Anthropic API integration in the app itself.

## Database — Tables Principales

Schema complet dans /supabase/schema.sql — ne jamais modifier sans instruction.

```
nodes            → arborescence folders + fiches (self-referential parent_id)
fiches           → contenu markdown des fiches (1-to-1 avec nodes type=fiche)
tags             → tags globaux (#pentest, #appsec...)
fiche_tags       → liaison many-to-many fiches <> tags
flashcards       → cartes SM-2 liées à une fiche
quiz_questions   → questions QCM liées à une fiche
review_sessions  → historique sessions (flashcard + quiz) pour progression
user_preferences → 1 seule ligne : theme + font_size
```

Fonctions Supabase disponibles :

- `get_node_progress(node_id)` → total_fiches, read_fiches, progress_pct
- `get_streak()` → int (jours consécutifs de révision)
- `global_search(query)` → résultats full-text cross-tables

## Supabase — Clients

Deux clients distincts, ne jamais les confondre :

```ts
// @/lib/supabase/server.ts — Server Actions et Server Components UNIQUEMENT
import { createClient } from "@supabase/supabase-js";
export const supabaseAdmin = createClient(
  process.env.NEXT_PUBLIC_SUPABASE_URL!,
  process.env.SUPABASE_SERVICE_ROLE_KEY!, // bypasse RLS — jamais exposé côté client
);

// @/lib/supabase/client.ts — Client Components uniquement (lecture)
import { createBrowserClient } from "@supabase/ssr";
export const supabase = createBrowserClient(
  process.env.NEXT_PUBLIC_SUPABASE_URL!,
  process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
);
```

Règle absolue : SUPABASE_SERVICE_ROLE_KEY uniquement côté serveur.
Jamais dans un Client Component, jamais dans une variable NEXT_PUBLIC_.

## Architecture Décisions

### Server vs Client Components

- Server Components par défaut pour tout fetch de données
- Client Components uniquement si : useState, useEffect, event handlers, animations
- Toujours utiliser les Server Actions pour les mutations Supabase (jamais d'API routes)

### Sidebar

- Fichier unique : @/components/layout/Sidebar.tsx
- Utilisé dans app/layout.tsx uniquement — jamais recréé dans les pages
- Structure et règles dans /docs/UI_RULES.md (section "Sidebar — Loi Fondamentale")

### Markdown Renderer

- Fichier unique : @/components/ui/MarkdownRenderer.tsx
- Gère : highlights Obsidian Highlightr, callouts [!info/danger/warning],
  code blocks, tables, wikilinks (texte stylé uniquement en V1)
- Specs complètes dans /docs/UI_RULES.md (sections Highlights + Callouts)

### Spaced Repetition (SM-2)

```ts
// Algorithme SM-2 — à implémenter dans Server Action
function sm2(easeFactor: number, intervalDays: number, quality: number) {
  // quality: 0=À revoir, 1=Difficile, 2=Bien, 3=Facile (mappé 0-5)
  const q = [0, 2, 4, 5][quality];
  const newEF = Math.max(
    1.3,
    easeFactor + 0.1 - (5 - q) * (0.08 + (5 - q) * 0.02),
  );
  const newInterval = q < 3 ? 1 : Math.round(intervalDays * newEF);
  return { easeFactor: newEF, intervalDays: newInterval };
}
```

## Script CLI — Import de Fiches

La génération du contenu (fiche, flashcards, quiz) est faite par Claude Code CLI
directement lors d'une conversation — pas d'appel API Anthropic dans l'app.
Le script se charge uniquement de l'import en base et dans Obsidian.

Fichier : scripts/import-fiche.ts
Usage :

```bash
npm run import-fiche -- \
  --theme "linux" --subtheme "permissions" \
  --fiche scripts/tmp/fiche.md \
  --flashcards scripts/tmp/flashcards.json \
  --quiz scripts/tmp/quiz.json
```

Format attendu flashcards.json :

```json
[{ "question": "...", "answer": "...", "security_angle": "..." }]
```

Format attendu quiz.json :

```json
[{
  "question": "...",
  "options": ["A", "B", "C", "D"],
  "correct_index": 1,
  "explanation": "...",
  "tag": "commandes"
}]
```

Étapes du script :

1. Résoudre ou créer le node parent :
   - Chercher folder slug=theme (parent_id IS NULL)
   - Si absent → créer le node theme (folder, root, color #6366F1)
   - Chercher folder slug=subtheme avec parent=theme
   - Si absent → créer le node subtheme (folder, parent=theme, color hérité)
2. Créer node (type=fiche) + insérer le contenu dans fiches
   - Si slug existe déjà → UPDATE content_md + updated_at (idempotent)
3. Écrire fiche.md dans le vault Obsidian :
   $OBSIDIAN_VAULT_PATH/[theme]/[subtheme]/[slug].md
   - Créer les dossiers récursivement si absents
   - Skip silencieusement si OBSIDIAN_VAULT_PATH non défini (warning uniquement)
4. Insérer flashcards[] — DELETE existantes avant réinsertion (idempotent)
5. Insérer quiz_questions[] — DELETE existantes avant réinsertion (idempotent)
6. Supprimer les fichiers dans scripts/tmp/ après import réussi
7. Output : "✅ [theme]/[subtheme] — X flashcards, Y questions"

Utilise SUPABASE_SERVICE_ROLE_KEY (Node.js, server-side uniquement).

## Workflow — Génération et import d'une fiche

Quand l'utilisateur demande une nouvelle fiche, Claude doit :

0. Identifier thème et sous-thème à partir de la demande.
   Si ambigu → demander confirmation avant de générer.
1. Générer le contenu (fiche.md, flashcards.json, quiz.json)
   selon les formats définis ci-dessus.
2. Écrire les 3 fichiers dans scripts/tmp/ (créer le dossier si absent).
3. Exécuter automatiquement :
   ```bash
   npm run import-fiche -- \
     --theme "[theme]" --subtheme "[subtheme]" \
     --fiche scripts/tmp/fiche.md \
     --flashcards scripts/tmp/flashcards.json \
     --quiz scripts/tmp/quiz.json
   ```
4. Confirmer le résultat à l'utilisateur.

Ne jamais demander à l'utilisateur de lancer le script manuellement.
Ne jamais laisser de fichiers dans scripts/tmp/ après un import réussi.
